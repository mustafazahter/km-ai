# Add a new channel

Every channel is a `Channel` subclass in `src/ai_bot/channels/<name>.py`; the allow-list, de-duplication, rate limit, chunking, approval code and commands live in `channels/base.py`. Use `channels/slack.py` (signed webhook) and `channels/email_channel.py` (polling, no-approval channel) as templates. Do not loosen the rules: while a channel is off its addresses return 404, **an empty allow-list = nobody can write**, the signature is verified before the body is parsed and with a constant-time comparison, and neither bodies nor secrets are written to the log.

1. **Class** (`channels/<name>.py`): class fields `name`, `title`, `prefix` (env prefix), `required` (required setting names), `max_chunk`, `paths = {"events": "/channels/<name>/events"}` (the inbound address; empty for a polling channel), `fields` (the panel form: `{"name", "label", "kind": secret|text|list|bool, "hint", "required"}`). Methods: `allow_setting()` (name of the allow-list setting), `normalise()` / `valid_entry()` / `entry_hint()` (ids entered in the list), `register(router)` (inbound route: `self.require_enabled()`, `read_body`, signature, parsing, `self.accept(...)` → `Inbound`, then `self.spawn(inbound)`; the webhook returns `200` right away), `send(ctx, text)` (send one chunk; `send_text` does the chunking), `test()` (check the token/identity without writing to anyone, `ChannelError(code, message)` for failures), `target_for(chat_id, external)` (the reply context for messages the bot writes first; `None` if unknown). If the sender cannot be proven (like e-mail), set `can_confirm = False`: tools that ask for approval are refused on that channel and commands that change something do not run (`src/ai_bot/commands.py`).
2. **Setting schema** (`channels/schema.py`): `<NAME>_ENABLED` (bool, default `False`), identity/address settings, `<NAME>_ALLOWED_*` (a list, with a pattern and `max_length`), and add the secret values to `SECRET_NAMES` (write-only). Nothing that carries a security lock enters the schema.
3. **Registration:** add the class and its import to the `for cls in (WhatsApp, Teams, Slack, Email)` tuple in `channels/manager.py`.
4. **System prompt:** add the name to the `PROMPT_CHANNELS` tuple in `agent.py`; in `config.py` (a `system_prompt_<name>` field + the `SYSTEM_PROMPT_<NAME>` env), in `runtime_config.py` (`Setting("SYSTEM_PROMPT_<NAME>", ...)`, `GROUP_OF`, `FIELD_MAP`).
5. **Panel:** in `ui/pages/channels.js` add `MARKS` (the icon; if missing add it to `ui/icons.svg`), `TAGLINES`, `GUIDES` (the step-by-step setup guide), `GROUPS` (form sections), `PATH_LABELS`, `PROMPT_NAME`, `PROMPT_HINT`, `GUIDE_TIME`; the `channel-<name>` help topic in `ui/help.js`; for the wizard `CHANNEL_INFO` in `ui/pages/setup.js` and `CHANNEL_CHOICES` in `panel.py`. Texts are written in Turkish and the English goes into `ui/i18n-en.js` (`python scripts/i18n_extract.py --missing`).
6. **Test** (`tests/test_channels_<name>.py`): use the `tests/test_channels_env.py` fixture (`chenv`; the network is imitated with a `Provider`, never go out to the real network). At least: 404 while off; a request with no or a wrong signature is rejected; with an empty allow-list or a sender not on the list the message does not reach the AI; an allowed sender gets a reply; a repeated message is handled once; a command like `/hafiza` runs without reaching the AI (the `tests/test_channel_commands.py` pattern); a secret does not come back in the panel (the `tests/test_channels_panel.py` pattern).
   ```bash
   .venv/bin/python -m pytest -q tests/test_channels_<name>.py tests/test_channels_panel.py tests/test_channel_commands.py
   ```
7. **Docs:** `docs/CHANNELS.md` and `docs/tr/CHANNELS.md` (summary table, security model, settings), `README.md` and `README.tr.md` (channel lists), `docs/ADMIN-UI.md` and `docs/tr/ADMIN-UI.md`.
